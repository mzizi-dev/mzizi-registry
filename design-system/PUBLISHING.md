# The design system: source and publishing

This folder **is** the mzizi design system. The published Design System artifact on claude.ai is built from it, file for file. Edit here, never on the artifact page: a change made only on the page is lost at the next publish.

- Published at: <https://claude.ai/artifact/G8CCtAbZ8w717uQ3R5itCc>

## Layout

Every file below is published at `project/<same path>` on the artifact, except this one.

| Path                                          | What                                                                                                    | Authored or generated                                                                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `design-system.json`                          | The artifact's index: title, namespace, asset groups (with the artifact's upload ids) and `lastChange`. | Authored. Update `lastChange` on every publish.                                                                                                      |
| `README.md`                                   | The brand book.                                                                                         | Authored.                                                                                                                                            |
| `tokens.json`                                 | Every token as data.                                                                                    | Generated by `pnpm design-system:generate` from `styles/globals.css` and `lib/tokens/`. CI fails if it drifts (`pnpm design-system:generate:check`). |
| `components/<Comp>/README.md`, `preview.html` | Usage notes and a static rendition of each N2 primitive.                                                | Authored, from the primitive named in the README's second line.                                                                                      |
| `components/bundle.css`, `index.d.ts`         | The renditions' stylesheet and the primitives' props.                                                   | Authored.                                                                                                                                            |
| `components/Cover/preview.html`               | The cover.                                                                                              | Authored.                                                                                                                                            |
| `assets/<Group>/README.md`                    | Notes for each asset group.                                                                             | Authored. The files themselves live in `components/registry/assets/`.                                                                                |

## Keeping it current

The design system changes whenever the components or tokens do:

- **Tokens.** A change to `styles/globals.css` or `lib/tokens/` needs `pnpm design-system:generate` in the same PR. CI enforces this.
- **Components.** A PR that changes a primitive with a rendition here updates its `components/<Comp>/` files too. `__tests__/design-system.test.ts` fails if a rendition names a source file that no longer exists, so a removed component cannot linger.
- **Marks.** A new or changed mark goes in `components/registry/assets/`, with its notes in `assets/<Group>/README.md`.

## Publishing

After a merge that touches this folder, republish the artifact from `main`. Ask Claude (in Claude Code or claude.ai) to "republish the design system from design-system/". It will:

1. upload any new files from `components/registry/assets/` and record their ids in `design-system.json`;
2. publish every changed file to the artifact URL above.

Uploads are content-addressed by the artifact, so the ids in `design-system.json` change only when a file does.
