# Mzizi — Copilot Instructions

When generating code in this repository:

1. Import icons from "@/lib/icons", never from "lucide-react"
2. Use cn() from "@/lib/utils" for className composition
3. Use CSS vars from N1 tokens: var(--color-cobalt), var(--radius-lg), etc.
4. Never use raw Tailwind colors (bg-red-500). Use semantic tokens.
5. Brand components (N3) must use useMziziHarness hook
6. All interactive elements need focus-visible:outline-2 and min-h-[48px] (48px is the minimum touch target; 56px is the default)
7. Add data-slot="component-name" to the root element
8. Add data-portal="https://mzizi.dev/components/{name}" next to data-slot
9. Status colors: var(--status-success), var(--status-error), var(--status-warning)
10. Font: inherit (N3 handles typography via font-serif). N6/N7 never set fonts directly.

# Tokens

Tokens are files in the registry: lib/tokens/palette.source.ts (the 21 colour families) and lib/tokens/brand.source.ts (semantic colours, typography, spacing). Never copy a value; reference the generated CSS variable.

11. Icons: size them with the mzizi-icons presets (`ICON_SIZES`, through `<Icon size="…">`): xs 12px, sm 16px, md 20px (the default), lg 24px, xl 32px. There are no `--icon-*` CSS variables
12. Touch targets: 56px by default, never below 48px (the accessibility block of brandMeta in lib/tokens/brand.source.ts)
13. Spacing: the 17-step spacing scale in brand.source.ts. Default component padding is base (16px), not md (12px, which is compact)
14. Density: density-aware components follow the density in their contract — do not hardcode tier behaviour
15. High contrast: when an HC theme is active, components use the semantic colours' hcLightValue/hcDarkValue overrides in brand.source.ts (null where none is defined)
16. Typography: use the type scale in brand.source.ts (Display, Display Small, H1-H6, Body Large/Body/Body Small, Caption, Code)

# Source location

17. Every component's source is a file in this repository: `components/registry/n<N>-<label>/<name>.astro`, `.rs` and `.tsx`, one file per build, all held to one contract in contracts/
18. There is no database copy of component source; registry.json indexes the files and api.mzizi.dev serves them from a pinned commit
19. To add a new component: write its contract, its builds and its registry.json item, run pnpm registry:normalize && pnpm registry:validate, add a CHANGELOG.md entry and open a pull request against staging

# RTL

20. Use logical CSS properties: margin-inline-start/end, padding-inline-start/end, inset-inline-start/end
21. Never write margin-left/right, padding-left/right, left/right (in inline styles or CSS)
22. text-align: use start/end, never left/right
23. Mark directional icons with data-rtl-mirror="true" so the rtl-conformity-check N8 component knows they intentionally flip

# Accessibility validation

24. Before shipping a new colour pair, check it with the mzizi_check_accessibility MCP tool against the Mzizi floor (APCA, AAA)
25. The palette's own pairs are measured with APCA by the registry's token tests (`__tests__/tokens-*.test.ts`) in CI

# Accessibility healing loop

26. The N8 assurance components mzizi-a11y-audit and rtl-conformity-check detect accessibility and RTL regressions at runtime.
27. mzizi-fundi-reporter (N9) files each regression as a GitHub issue on the registry.
28. Humans review and merge the fix; healing is never auto-merged.
