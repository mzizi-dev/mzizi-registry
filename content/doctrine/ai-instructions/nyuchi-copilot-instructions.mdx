# Mzizi — Copilot Instructions

When generating code in this repository:

1. Import icons from "@/lib/icons", never from "lucide-react"
2. Use cn() from "@/lib/utils" for className composition
3. Use CSS vars from N1 tokens: var(--color-cobalt), var(--radius-lg), etc.
4. Never use raw Tailwind colors (bg-red-500). Use semantic tokens.
5. Brand components (N3) must use useNyuchiHarness hook
6. All interactive elements need focus-visible:outline-2 and min-h-[48px]
7. Add data-slot="component-name" to the root element
8. Add data-portal="https://mzizi.dev/components/{name}" next to data-slot
9. Status colors: var(--status-success), var(--status-error), var(--status-warning)
10. Font: inherit (N3 handles typography via font-serif). N6/N7 never set fonts directly.

# Tokens

11. Icons: use styling-icon-sizes (var(--icon-xs) 12px through var(--icon-xl) 40px, default 20px)
12. Touch targets: styling-touch-targets — comfortable (48px) is the default, never go below 44px (WCAG 2.5.5)
13. Spacing: styling-spacing 17-step scale. Default component padding is base (16px), not md (12px which is now compact)
14. Density: density-aware components reference styling-density tiers (compact, comfortable, spacious) — do not hardcode tier behaviour
15. High contrast: when an HC theme is active, components read styling-semantic-colors.hc_light_value/hc_dark_value
16. Typography: use styling-typography rows (Display, Display Small, H1-H6, Body Large/Body/Body Small, Caption, Code) plus letter_spacing and fluid_min_px/fluid_max_px for responsive type

# Source location

17. Production source for every stable component lives in components.source_code in Supabase
18. The frontend repo pulls from the DB at build time — do not maintain a separate copy of component source
19. To add a new component: write the source via SQL into components.source_code and flip status to stable

# RTL

20. Use logical CSS properties: margin-inline-start/end, padding-inline-start/end, inset-inline-start/end
21. Never write margin-left/right, padding-left/right, left/right (in inline styles or CSS)
22. text-align: use start/end, never left/right
23. Mark directional icons with data-rtl-mirror="true" so the rtl-conformity-check N8 component knows they intentionally flip

# Accessibility validation

24. Before shipping a new color pair, validate via SELECT calculate_contrast_ratio(fg_hex, bg_hex) — must hit 4.5 for normal text, 7.0 for AAA
25. Pairs are tracked in styling-accessibility-checks — query before assuming a combination is safe

# Accessibility healing loop

26. An N8 accessibility-audit component runs daily via pg_cron validating every color pair against protanopia/deuteranopia/tritanopia/achromatopsia simulations. Regressions auto-file Fundi issues.
27. Use simulate_color_blindness(hex, cb_type) to preview how a color appears under each condition.
28. Use run_accessibility_audit() to trigger a manual audit (e.g. in CI).
