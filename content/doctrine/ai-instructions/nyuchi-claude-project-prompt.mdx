You are working on Mzizi — the open design system and DNA-double-helix frontend architecture, governed by Mzizi and operated by nyuchi, that powers the bundu ecosystem (mukoko, nyuchi, shamwari, bundu, Mukoko Events).

═══════════════════════════════════════════════
NO HARDCODED NUMBERS
═══════════════════════════════════════════════

This prompt deliberately contains no counts. Component counts, node counts, and token counts drift as the system evolves. When you need a current number, read it live:

- GET https://api.mzizi.dev/v1/stats — per-node component counts
- meta.registryTotal on GET https://api.mzizi.dev/v1/ui — the registry total
- mzizi_get_architecture (MCP) or GET /v1/architecture — every node and rung with its strand, covenant, rules, and live counts
- mzizi_get_architecture with a node number — one node's covenant, stakeholder and rules
- GET /v1/changelog — the releases, newest first

═══════════════════════════════════════════════
THE DNA DOUBLE HELIX
═══════════════════════════════════════════════

Two entwined backbones, held together by cross-cutting rungs. Node numbers are
labels, not a sequence, and the set is never capped — read mzizi_get_architecture
for the live model rather than assuming a range.

ENGINEERING BACKBONE — strands, and the nodes that sit on them:
core-guarantee N2 Primitives · N4 Safety · N5 Resilience · N8 Assurance
"The guarantees travel unchanged, always."
shipped N3 Brand · N6 Pages · N7 Shell
"In the box, but free to evolve."
swappable N1 Tokens
"Fork along the seams, not everywhere."
spine the harness — "what makes the parts one body."

MEANING BACKBONE:
genetic-code Ubuntu doctrine + Mzizi conventions —
"the sequence everything is read from."
transcription "Doctrine is data, not tribal knowledge."

RUNGS — cross-cutting, bridging both backbones, bound to no single strand:
N9 Fundi "Failure is a learning event." (self-healing)
N10 Documentation "The system documents itself."
N11 Discovery "If the machine can't see it, it doesn't exist." (SEO/AIO)

A node consumes from the strand below it on the same backbone — never
sideways and never upward. Rungs bridge both backbones and are never
imported by a node.

Each node's components live in ONE directory under `components/registry/`, named `n<N>-<label>`:
n1-tokens / n2-primitives / n3-brand / n4-safety / n5-resilience / n6-pages / n7-shell / n8-assurance / n9-fundi / n10-documentation / n11-discovery. Read the live set from the repository rather than assuming this list is complete.

═══════════════════════════════════════════════
SOURCE CODE LIVES IN THE REGISTRY REPOSITORY
═══════════════════════════════════════════════

There is no database behind the registry. registry.json and the files on disk in mzizi-dev/mzizi-registry are the whole data layer, and api.mzizi.dev and mcp.mzizi.dev serve them from a pinned commit.
A component is one file per build in `components/registry/n<N>-<label>/`: `<name>.astro` (the default), `<name>.rs` (Mzizi Roots, Dioxus) and `<name>.tsx` (React), all held to one contract in `contracts/`.
When you add or modify a component, change its files, its contract and its registry.json item in a pull request against staging, with a CHANGELOG.md entry.

═══════════════════════════════════════════════
IMPLEMENTATION RULES
═══════════════════════════════════════════════

1. CSS values live only in N1 tokens. Other nodes reference via var().
2. Icons come from @/lib/icons (mzizi-icons registry). Never import lucide-react directly.
3. N2 primitives never import useMziziHarness. They use cn() for classNames and carry data-slot.
4. N3 brand components always destructure { log, motion, LiveRegion } from useMziziHarness.
5. N3 brand components always use the mzizi- prefix in their name.
6. N6 pages are pure composition — no inline buttons, cards, SVGs, or brand fonts.
7. Every component has data-slot and data-portal attributes.
8. All status colors use semantic tokens (--status-success, --status-error, etc).
9. Third-party brand colors (Ethereum, Google, EcoCash) are the only raw hex exceptions.
10. Buttons, inputs, avatars, badges, toggles are ALWAYS pill-shaped (borderRadius: 9999).
11. Touch targets default to 56px; 48px is the minimum (the accessibility block of brandMeta in lib/tokens/brand.source.ts).
12. Density-aware components follow the density in their contract, never hardcode tier behaviour.
13. RTL support: use logical CSS properties (margin-inline-start, padding-inline-end), not physical. rtl-conformity-check N8 validates this at runtime.
14. Versioning: a merge into staging is a patch; a release to main is the next minor above the highest tag; a major is released only by hand.
15. Fundi creates GitHub issues for failures — humans stay in the loop.

═══════════════════════════════════════════════
DESIGN TOKENS — FILES IN THE REGISTRY
═══════════════════════════════════════════════

N1 tokens are files, edited by pull request:

- lib/tokens/palette.source.ts — the 21 colour families: seven minerals, seven heritage tones, seven experimental colours. The one source of the palette.
- lib/tokens/brand.source.ts — semantic colours, typography, spacing and the ecosystem brands.

pnpm tokens:sync generates every artifact from them (styles/globals.css, lib/tokens/palette.generated.ts and the per-platform token files in components/registry/n1-tokens/); pnpm tokens:verify fails CI on drift.
Read tokens with mzizi_get_tokens or GET https://api.mzizi.dev/v1/brand rather than assuming values.

═══════════════════════════════════════════════
ACCESSIBILITY VALIDATION
═══════════════════════════════════════════════

- mzizi_check_accessibility (MCP) — contrast and colour-vision checks against the Mzizi APCA/AAA floor, computed locally
- The registry's token tests (`__tests__/tokens-*.test.ts`) measure every colour family against the base surface with APCA in CI

═══════════════════════════════════════════════
RECORDING CHANGE
═══════════════════════════════════════════════

- CHANGELOG.md — every change that alters behaviour, shipped content, an API response, a package, a default or a documented fact adds an entry under ## [Unreleased] in the same pull request
- content/changelog/releases.json — the machine-readable record of each release, served at GET /v1/changelog
- Component version history is machine-written data owned by the Mzizi console (app.mzizi.dev), not the registry

═══════════════════════════════════════════════
RENAMES
═══════════════════════════════════════════════

lib/component-renames.json maps each former name to its successor, and the API and MCP resolve former names.
After a rename, update the registryDependencies of every item that names it; pnpm registry:validate fails on one that does not resolve.

═══════════════════════════════════════════════
