# Node Decision Guide — Where Does a Component Belong?

Every artifact belongs to exactly **one** place on the Mzizi DNA helix. Choose by what the artifact *is*, not by what it talks to. If a component would straddle two places, it is two components. There are **no axes and no outliers** — the model is nodes on strands, plus cross-cutting rungs.

This guide is the current, authoritative decision tree. (It replaces the older `layer-decision-guide`, retained only as a superseded redirect.)

## First: node, strand, or rung?

- Most components are **nodes** sitting on a **strand** (a backbone grouping).
- A few cross-cutting concerns are **rungs** — base pairs bridging the two backbones; they belong to no single strand.
- The **strands** themselves are documented in `documentation-architecture-strands/*`.

## Decision table

| If the artifact is… | Place | strand | `component_documents` collection |
| -- | -- | -- | -- |
| A CSS value, colour, spacing, motion, radius, breakpoint | **N1** node | swappable | one of the `styling-*` collections |
| A generic UI element with no brand assumptions (button, card, input, dialog) | **N2** node | core-guarantee | `primitives` |
| A Nyuchi-branded composition using the minerals + harness | **N3** node | shipped | `brand` |
| A conditional-rendering guard (permission, geo, rate limit) | **N4** node | core-guarantee | `safety` |
| A failure-case handler (error boundary, skeleton, offline banner, fallback) | **N5** node | core-guarantee | `resilience` |
| A full-screen page composition | **N6** node | shipped | `pages` |
| The app container (navigation, routing, lifecycle, theme) | **N7** node | shipped | `shell` |
| Instrumentation (monitoring, chaos, probes, a11y audit, RTL conformity) | **N8** node | core-guarantee | `observability` / `observability-domains` |
| Automated self-healing responding to N8 detections | **N9** rung | — | `fundi` |
| Documentation, AI instructions, docs infrastructure | **N10** rung | — | `documentation*` |
| Making a surface machine-discoverable (OG/preview images, JSON-LD, llms.txt) | **N11** rung | — | cross-cutting |

Doctrine, Ubuntu pillars/principles, and Bundu conventions are not component nodes — they live in the `genetic-code-*` collections (the genetic-code strand).

## The rules that follow from the node

- **N1** is the only place raw CSS values live. Every other node consumes them via `var(--token-name)`.
- **N2** never imports `useNyuchiHarness`; it uses `cn()` and carries `data-slot`.
- **N3** always uses the `nyuchi-` prefix and destructures `{ log, motion, LiveRegion }` from the harness.
- **N6** is pure composition — no inline buttons, cards, or SVGs; those come from N2/N3.
- **N4/N5/N8** wrap components rather than render them.
- **Rungs (N9–N11)** are cross-cutting; they bridge the strands rather than sit on one.

## How to check what already lives in a node

```sql
-- everything in a node, by collection
SELECT collection, count(*) FROM component_documents
WHERE node = 3 GROUP BY collection;
```

Or call the MCP at `mcp.mzizi.dev/mcp`: `get_node_categories(N)` for the category breakdown, `get_node_detail(N)` for the covenant and rules, `get_node_documents(p_node => N)` for the documents themselves.
