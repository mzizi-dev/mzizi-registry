# Node Decision Guide — Where Does a Component Belong?

Every artifact belongs to exactly **one** place on the Mzizi DNA helix. Choose by what the artifact _is_, not by what it talks to. If a component would straddle two places, it is two components. There are **no axes and no outliers** — the model is nodes on strands, plus cross-cutting rungs.

This guide is the current, authoritative decision tree. (It replaces the older `layer-decision-guide`, retained only as a superseded redirect.)

## First: node, strand, or rung?

- Most components are **nodes** sitting on a **strand** (a backbone grouping).
- A few cross-cutting concerns are **rungs** — base pairs bridging the two backbones; they belong to no single strand.
- The **strands** themselves are documented in `documentation-architecture-strands/*`.

## Decision table

| If the artifact is…                                                          | Place        | strand         | Directory under `components/registry/`                |
| ---------------------------------------------------------------------------- | ------------ | -------------- | ----------------------------------------------------- |
| A CSS value, colour, spacing, motion, radius, breakpoint                     | **N1** node  | swappable      | `n1-tokens/` (the source is `lib/tokens/*.source.ts`) |
| A generic UI element with no brand assumptions (button, card, input, dialog) | **N2** node  | core-guarantee | `n2-primitives/`                                      |
| A Nyuchi-branded composition using the minerals + harness                    | **N3** node  | shipped        | `n3-brand/`                                           |
| A conditional-rendering guard (permission, geo, rate limit)                  | **N4** node  | core-guarantee | `n4-safety/`                                          |
| A failure-case handler (error boundary, skeleton, offline banner, fallback)  | **N5** node  | core-guarantee | `n5-resilience/`                                      |
| A full-screen page composition                                               | **N6** node  | shipped        | `n6-pages/`                                           |
| The app container (navigation, routing, lifecycle, theme)                    | **N7** node  | shipped        | `n7-shell/`                                           |
| Instrumentation (monitoring, chaos, probes, a11y audit, RTL conformity)      | **N8** node  | core-guarantee | `n8-assurance/`                                       |
| Automated self-healing responding to N8 detections                           | **N9** rung  | —              | `n9-fundi/`                                           |
| Documentation, AI instructions, docs infrastructure                          | **N10** rung | —              | `n10-documentation/`                                  |
| Making a surface machine-discoverable (OG/preview images, JSON-LD, llms.txt) | **N11** rung | —              | `n11-discovery/`                                      |
| An agent skill                                                               | **N12** rung | —              | none: published as `@nyuchi/mzizi-skills`             |

Doctrine, Ubuntu pillars/principles, and Mzizi conventions are not component nodes — they live in the `genetic-code-*` collections (the genetic-code strand).

## The rules that follow from the node

- **N1** is the only place raw CSS values live. Every other node consumes them via `var(--token-name)`.
- **N2** never imports `useMziziHarness`; it uses `cn()` and carries `data-slot`.
- **N3** always uses the `mzizi-` prefix and destructures `{ log, motion, LiveRegion }` from the harness.
- **N6** is pure composition — no inline buttons, cards, or SVGs; those come from N2/N3.
- **N4/N5/N8** wrap components rather than render them.
- **Rungs (N9–N12)** are cross-cutting; they bridge the strands rather than sit on one.

## How to check what already lives in a node

- `GET https://api.mzizi.dev/v1/search?node=3` — every component in a node
- `mzizi_list_components` with `node` on the MCP at `mcp.mzizi.dev/mcp` — the same, with owner, collection and Rust filters
- `mzizi_get_architecture` with `node` — the node's covenant, stakeholder and rules
- or list `components/registry/n<N>-*/` in the registry repository
