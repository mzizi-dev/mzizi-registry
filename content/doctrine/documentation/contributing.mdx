# Contributing

Mzizi is open source and built by the community. Ubuntu — I am because we are.

## Repository

github.com/mzizi-dev/mzizi-registry. Its `CONTRIBUTING.md` and `AGENTS.md` are the full process; this page is the summary.

## Source code lives in the repository

Every component's source is a file in the registry, `components/registry/n<N>-<node>/<name>.<ext>`, with one sibling file per build: `.astro` (the default), `.rs` (Mzizi Roots, Dioxus) and `.tsx` (React). There is no database copy. `registry.json` indexes the files, and api.mzizi.dev serves them from a pinned registry commit. To add or change a component, change its files and open a pull request.

## Adding a New Component

1. Decide which node it belongs to (see Node Decision Guide).
2. Write its contract first, `contracts/<family>/<name>.contract.json`: the props, states, clauses, checks and density every build is tested against.
3. Write the builds under `components/registry/n<N>-<node>/`: the `.astro` first, then the `.tsx` and the `.rs`, each the same component. A `.rs` held to a contract carries a `pub const CONTRACT` that `pnpm contracts:sync` fills.
4. Add its item to `registry.json` (name, type, description, dependencies, files and the `meta` block), then run `pnpm registry:normalize && pnpm registry:validate`.
5. Meet the node's enterprise criteria below, including the `data-slot` and `data-portal` attributes.
6. Add an entry under `## [Unreleased]` in `CHANGELOG.md`.
7. Run `pnpm check`, which runs every gate CI runs; for a `.rs`, also the `mzizi-rs` gate (`cargo fmt`, `cargo clippy`, `cargo test`).
8. Open a pull request against `staging`, with a `Site/docs/skills impact` section in its body.

## Enterprise Criteria Checklist

### N2 (Primitives)

- [ ] No useMziziHarness import
- [ ] data-slot attribute on root element
- [ ] data-portal attribute pointing to mzizi.dev/components/{name}
- [ ] cn() for className composition
- [ ] Zero raw Tailwind colors
- [ ] Import icons from @/lib/icons
- [ ] Touch targets 56px by default, 48px minimum
- [ ] If pill-shaped category (button, input, avatar, badge, toggle), use borderRadius 9999

### N3 (Brand)

- [ ] mzizi- prefix on the name
- [ ] useMziziHarness with full destructure { log, motion, LiveRegion }
- [ ] animStyle with motion.prefersReduced check
- [ ] ARIA role or aria-label
- [ ] data-slot and data-portal attributes
- [ ] focus-visible ring on interactive elements
- [ ] Touch targets on buttons at least 48px (`min-h-[48px]`), 56px by default
- [ ] I18N (Intl formatters for dates, numbers, currency)
- [ ] Semantic tokens for status-bearing colors

### N6 (Pages)

- [ ] Pure composition — no inline buttons, cards, or SVGs
- [ ] Accept children/slots for content
- [ ] Semantic CSS vars only (bg-card, text-foreground, bg-primary)
- [ ] Loading state prop
- [ ] role="main" and aria-label
- [ ] data-slot and data-portal

### N8 (Assurance)

- [ ] TypeScript module exporting typed functions and React hooks
- [ ] Banner comment identifying node and purpose
- [ ] Configurable rules array
- [ ] Optional onViolation/onComplete callbacks
- [ ] React hook variant for continuous monitoring

## Accessibility Validation

Before shipping a new colour pair, check it against the Mzizi floor (APCA, AAA) with the `mzizi_check_accessibility` MCP tool on mcp.mzizi.dev, which computes contrast and colour-vision results locally. The palette's own pairs are checked in CI by the registry's token tests (`__tests__/tokens-*.test.ts`), which measure every family against the base surface with APCA.

## RTL Support

Use logical CSS properties (margin-inline-start, padding-inline-end, inset-inline-start) not physical (margin-left, padding-right, left). Use text-align: start/end not left/right. Mark directional icons with data-rtl-mirror="true". The rtl-conformity-check N8 component validates these rules at runtime.

## Versioning

Record the change in the same pull request: an entry under `## [Unreleased]` in `CHANGELOG.md`, headed `### <Kind> — <what changed> (<date>, #<PR>)`. The `changelog / entry required` check fails a pull request without one. See `documentation/changelog-system`.

Releases follow the org versioning policy: a merge into `staging` is a patch, a release to `main` is the next minor above the highest tag, and a major is only released by hand. Component version history is machine-written data that belongs to the Mzizi console, not to the registry.

## Fundi Integration

When N8 detects an issue with your component, Fundi creates a GitHub issue with structured labels. You can find issues related to your component at:

github.com/mzizi-dev/mzizi-registry/issues?q=label:fundi:node/{your-node}
