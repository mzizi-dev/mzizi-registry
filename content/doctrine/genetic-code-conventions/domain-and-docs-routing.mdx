# Domain and docs routing

Recorded 2026-05-22. Canonical guideline for where ecosystem surfaces live.

## Three surfaces per project

Every Bundu Foundation project has three surfaces, on three homes:

1. **Tooling** -> the project's own **branded domain**. The functional app —
   registry, API, MCP. The branded domain serves a slim one-pager landing;
   everything else under it is the project itself. Example: Mzizi -> `mzizi.dev`.
2. **Information** -> a **Bundu subdomain**, `<project>.bundu.org` (ASF-style —
   like `<project>.apache.org`). The project mini-site / explainer. Example:
   `mzizi.bundu.org`.
3. **Documentation** -> `docs.bundu.org`, under a **top-level path per project**:
   `docs.bundu.org/<project>`. Example: `docs.bundu.org/mzizi`.

## Documentation

- **`docs.bundu.org`** — one Starlight site, one repo (`bundu-docs`), holding
  the docs for every Bundu Foundation project and initiative. Each project is a
  top-level content folder (`mzizi/`, `siafudb/`, ...). One build, one deploy,
  unified search and navigation.
- **`docs.nyuchi.com`** — Nyuchi's own docs, separate repo (`nyuchi-docs`).
  Nyuchi and Bundu are legally separate entities — Bundu is research and
  governance, Nyuchi is commercial — so they do not share a docs surface.
- Project docs live in the `bundu-docs` repo, NOT the project's code repo. A
  project keeps its own code/tooling repo; its documentation is a
  Foundation-owned artifact consolidated in `bundu-docs`.

## Research

- All research is published via the Sanity studio onto `bundu.org/research`.

## Deployment

- Everything deploys to **Cloudflare Workers**. Sites, tools, APIs, MCP
  servers — one platform, one deploy story, one place to look when something
  is down.
- A site is a Worker with **Static Assets**: Astro emits HTML and assets, and
  the Worker serves them. `docs.nyuchi.com` already runs this way.
- **Vercel is being removed.** It was the rule for sites and is now the
  exception being retired: `mzizi.dev` is still served by Vercel until its
  Astro migration lands, and nothing new goes there.

The reason is not price or preference. Two deploy targets means two sets of
environment variables, two build configurations, two runtime models, and two
answers to "where does this run" for every new surface — and the split ran
straight through the middle of single products, with a site on one platform
calling an API on the other.
